## 2. Go 原生核心构建

### 2.1 Android（生成 libduanju_core.so）

统一入口（自动定位 NDK clang、设置 GOARM 与变体参数）：

```bash
python3 scripts/build_native.py --platform android --all-sources [--abi arm64-v8a]
```

等价的手动命令（arm64 示例）：

```bash
cd native
export ANDROID_NDK_HOME=/path/to/ndk
export GOOS=android GOARCH=arm64 CGO_ENABLED=1
export CGO_LDFLAGS='-Wl,-z,max-page-size=16384'
export CC=$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/<host>/bin/aarch64-linux-android26-clang

go build -mod=mod -trimpath -buildmode=c-shared \
  -ldflags='-s -w -X duanjuapp/native/core.buildAllSources=<true|false>' \
  -o ../android/app/src/main/jniLibs/arm64-v8a/libduanju_core.so ./bridge
```

其他 ABI 类似：armeabi-v7a 用 `armv7a-linux-androideabi26-clang` 并需 `GOARM=7`，x86_64 用 `x86_64-linux-android26-clang`（`GOARCH=amd64`）。

### 2.2 Windows（生成 duanju_core.dll）

```bash
python3 scripts/build_native.py --platform windows --all-sources
```

等价的手动命令（需 MinGW-w64 工具链）：

```bash
cd native
GOOS=windows GOARCH=amd64 CGO_ENABLED=1 CC=x86_64-w64-mingw32-gcc \
    go build -mod=mod -trimpath -buildmode=c-shared \
    -ldflags='-s -w -X duanjuapp/native/core.buildAllSources=<true|false>' \
    -o ../windows/runner/duanju_core.dll ./bridge
```

### 2.3 iOS（生成 framework）

```bash
cd native
# 需在 macOS + Xcode 环境
# 两种架构：arm64 (device) + amd64 (simulator)
GOOS=ios GOARCH=arm64 CGO_ENABLED=1 go build -buildmode=c-shared -o core-arm64.dylib bridge/main.go
# 然后 lipo 合并 → DuanjuCore.framework
```

iOS 端已提供 `DuanjuCore.podspec` 和 `DuanjuCoreAnchor`。

## 3. Flutter 构建

### 3.1 构建脚本

`scripts/app_build.py` 定义构建变体（`BuildVariant` 数据类：变体名、slug、`--dart-define` 与 Go linker 参数），各平台构建入口如下：

```bash
# Android 全流程：build_native → pub get → flutter build apk --split-per-abi → package_release
python3 scripts/build_android.py                # 红果鉴（默认，仅红果站源）
python3 scripts/build_android.py --all-sources  # 真果鉴（全站源）

# Windows 全流程：build_native → pub get → flutter build windows → package_release
python3 scripts/build_windows.py [--all-sources]

# 仅编译 Go 原生核心（android / windows / darwin）
python3 scripts/build_native.py --platform android --all-sources

# 打包发布（校验产物完整性，生成 SHA256SUMS.txt）
python3 scripts/package_release.py --platform android --all-sources
```

### 3.2 手动 Flutter 命令

```bash
# Debug 模式（红果鉴）
flutter run -t lib/main.dart

# Release APK
flutter build apk --release

# Release Windows
flutter build windows --release

# 全站源变体
flutter run --dart-define=ALL_SOURCES=true
```

> `lib/app_build.dart` 是仓库内静态文件（`allSourcesEnabled = bool.fromEnvironment('ALL_SOURCES')`），由 `--dart-define` 在编译期注入，不由脚本生成。

### 3.3 构建变体

变体由两侧参数共同决定，应用启动时校验一致（`core_bridge.dart` 比对 Dart 常量与 Go 上报的 `allSources`）：

```dart
// lib/app_build.dart（仓库静态文件，编译期由 --dart-define 注入）
const allSourcesEnabled = bool.fromEnvironment('ALL_SOURCES');  // 红果鉴 false, 真果鉴 true
const appName = allSourcesEnabled ? '真果鉴' : '红果鉴';
```

```go
// native/core/app_build.go（go build -ldflags -X 注入）
var buildAllSources = "false"
```

`allSourcesEnabled` 控制：
- `SourceSite.values` 包含全部站源 还是 仅 hongguo
- 首页是否显示所有站源入口
- Go 核心是否初始化非红果 Provider

## 4. CI/CD

构建/发布工作流（build.yml、publish-release.yml、convert-ios-ipa.yml）已移除
（commit `386475e`），发布改为本地 `scripts/build_*.py` 手动触发。当前仅保留测试门禁：

| 工作流 | 文件 | 触发 | 说明 |
| --- | --- | --- | --- |
| test | test.yml | push(main) / PR | `flutter analyze`（error 卡死）+ 分文件双变体测试门禁 |

门禁判据（`scripts/test_matrix.py`）：

- 红名单以「分文件 × 双变体（default / `ALL_SOURCES=true`）」**实测**结果为准，不做静态豁免表；
- 零豁免：workflow 不使用 `continue-on-error`，任何实测红即阻断；
- 本地复现：`python scripts/test_matrix.py [--only <文件>] [--variant all|default|both]`，
  退出码 1 = 红名单非空。

收紧原则：测试红先修（产品 bug 修产品，用例过时改用例）；确属环境依赖且不可修的，
先本地复现留档，再评估对具体 step 加 `continue-on-error` 并注明原因与复核日期。

## 5. 运行时行为

### 5.1 Android

- 首次启动：申请存储权限（下载目录）
- 下载：前台服务 + 通知栏进度
- PiP（画中画）：API 26+ 支持，手动触发
- 包体积：含 Go .so + media_kit + ffmpeg

- 窗口：默认尺寸 1080×1920，可拖动调整
- 画质增强：唯一支持平台（Anime4K + FSRCNNX shader）
- 全局快捷键：空格/方向键/M/F/Esc
- 下载：保持应用运行

### 5.3 iOS（暂缓）

- 下载：前台下载，后台暂停
- 媒体库：原生 Assets 框架集成（待实现）
- 后台任务：原生 BackgroundTasks（待实现）

## 7. 目录约定

### 7.1 数据目录（设备端）

| 平台 | 路径 |
| --- | --- |
| Android | `/data/data/com.duanju.app/files/` 或用户选择的 SD 卡路径 |
| Windows | `%APPDATA%\duanju_app\` + 用户选择的下载目录 |
| iOS | `Documents/duanju_app/` |

目录结构：
```
[app_data]/
├─ downloads/           # 下载的原始视频文件
├─ catalog/             # 目录缓存 SQLite
├─ covers/              # 封面图片缓存
├─ preferences/         # SharedPreferences XML 文件
├─ sessions/            # 播放会话临时文件
└─ merge/               # 合并导出产物
```

### 7.2 源码目录

```

├─ lib/                 # Flutter UI 层
├─ native/
│   ├─ bridge/          # FFI 桥接 main.go
```

## 8. 版本发布流程

按 `AGENTS.md` 约定：

```bash
# 1. 修改 pubspec.yaml 版本号
# version: 0.2.55+61  →  version: 0.2.56+62

# 2. 执行收尾同步（会构建纯源码镜像 + 生成 zip）
python3 scripts/finish_task.py --message "本次实际完成的变更"

# 3. 验证同步一致
python3 scripts/sync_source.py --check
```

`finish_task.py` 行为：
- 同步干净源码到同级 `../guoapp`（排除 SDK、依赖目录、缓存、签名）
- 生成 `真果·鉴-YYYYMMDDHHMM.zip` 纯源码压缩包
- 同一分钟重复执行追加序号

## 9. 常见开发任务速查

| 任务 | 操作 |
| --- | --- |
| 新增短剧站源 | 在 `provider_duanju_dispatch.go` 添加 case + 新建 `provider_duanju_xxx.go` |
| 新增传统站源 | 新建 `provider_xxx.go` + 在 `Downloader` 添加字段 + `app_requests.go` 添加入口 |
| 新增分类接口 | 实现 `fetchXxxCategories()` + 在 `provider_duanju_dispatch.go` / `app_categories.go` 添加 |
| 调整并发/限流 | 修改 `defaultConfig()` → `Config.PageSize`, `Config.Retries` 或 `config_defaults.go` |
| 修改错误处理 | 各 `fetch*` / `resolve*` 方法返回 error，上层由 `app_requests.go` 统一包装 |
| 新增缓存策略 | `app_catalog_cache.go` / `app_covers.go` 分别管理目录和封面 |
| Flutter 调 Go 新接口 | `nativeInput` 增加字段 → `app_requests.go` 处理新 command → `NativeRepository` 加 Future 方法 |
